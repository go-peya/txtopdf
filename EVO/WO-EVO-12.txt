## 2.10. Detalle de Logros del Hito G40 y Distinción Arquitectónica (G32 vs G40)

### Distinción entre Continuidad de Memoria (G32) y Continuidad Operativa de Flujo de Trabajo (G40)

- **G32 (Continuidad Epistémica y de Memoria de Dominio):** Permite que un agente recupere hechos verificados, restricciones arquitectónicas, investigaciones previas y linaje de decisiones (`KnowledgeTMS` + `BM25Engine`) cuando sabe qué consultar, evitando alucinaciones ($K=0$) y re-investigaciones redundantes. Sin embargo, el motor de búsqueda por sí solo no define cuál es el objetivo activo de ejecución, qué criterios de aceptación faltan por satisfacer, qué tareas ya fueron completadas con evidencia verificable ni cuál es la siguiente acción concreta.
- **G40 (Continuidad Operativa Determinista — `WorkstreamState` Contract):** Construye sobre la base epistémica de G29–G39 un contrato determinista y versionado (`CANONICAL_WORKSTREAM_CONTRACT_VERSION = 1`) que permite a una sesión completamente nueva (proceso en frío sin historial conversacional) reconstruir en una única operación de solo lectura (`< 10 ms`) las 6 dimensiones operativas del trabajo activo: (1) objetivo activo y criterios de aceptación, (2) decisiones vigentes vinculadas por ID a `KnowledgeTMS`/`ADR` con exclusión automática de decisiones sustituidas, (3) trabajo completado con evidencia verificable obligatoria, (4) cola de tareas en curso y pendientes con grafo de dependencias acíclico, (5) bloqueos abiertos y (6) siguiente acción recomendada (`nextAction`) determinista y justificada.

## 4. SLSA Provenance Level Assessment

In strict accordance with OpenSSF supply chain governance, **SLSA Level 3 is NOT declared on local development environments**:

| SLSA Level | Requirements | Local State | CI/CD Pipeline State |
| :--- | :--- | :--- | :--- |
| **SLSA 1** | Build process documented; provenance generated. | **ACHIEVED** (Local hashes, manifests, and test runs documented). | **ACHIEVED** |
| **SLSA 2** | Version-controlled source; hosted build service; signed provenance. | **PARTIAL** (Git controlled, but running on local developer host). | **ACHIEVED** |
| **SLSA 3** | Isolated build environment; unforgeable provenance; non-falsifiable OIDC identity; hermetic dependencies. | **NOT ATTAINABLE LOCALLY** (Workstation filesystem is mutable). | **READY VIA WORKFLOW** (`.github/workflows/release-attestation.yml`). |

> [!IMPORTANT]
> A valid SLSA Level 3 attestation requires execution inside an ephemeral, tamper-resistant GitHub Actions runner with cryptographic OIDC identity token exchange. Declaring SLSA Level 3 on local builds is explicitly forbidden. Local artifacts hold declared provenance and candidate verification.

## 5. Automated CI/CD Attestation Pipeline

The automated signing and attestation pipeline is configured in `.github/workflows/release-attestation.yml`:

```yaml
permissions:
  contents: read
  id-token: write
  attestations: write
```

### 5.1 Pipeline Steps
1. **Clean Checkout**: Immutable checkout pinned to the release tag (`actions/checkout@v4`).
2. **Deterministic Build**: Node.js 22.15.0 LTS with `npm ci` and `npm run build`.
3. **Full Harness Regression**: Executes safe test runner suites via `node scripts/safe-test-runner.js`.
4. **Tarball Packaging**: `npm pack` generating `.work/artifacts/evocara-1.0.0.tgz`.
5. **Keyless Signing**: Cosign signs the blob using ephemeral OIDC tokens issued by GitHub's OIDC provider (Fulcio CA & Rekor transparency log).
6. **SLSA Attestation**: `actions/attest-build-provenance@v2` generates a non-forgeable in-toto predicate attached to the GitHub release.

### 5.2 Verification of Signed Artifacts

Once signed by CI/CD, downstream consumers verify the artifact using:

```bash
# Verify Cosign signature against GitHub OIDC workflow identity
cosign verify-blob \
  --certificate evocara-1.0.0.tgz.pem \
  --signature evocara-1.0.0.tgz.sig \
  --certificate-identity-regexp "^https://github.com/Blueisazul/Evocara/" \
  --certificate-oidc-issuer "https://token.actions.githubusercontent.com" \
  evocara-1.0.0.tgz

# Verify SLSA provenance via GitHub CLI
gh attestation verify evocara-1.0.0.tgz --repo Blueisazul/Evocara
```
